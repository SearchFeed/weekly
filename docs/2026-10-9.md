# 前端&AI技术双周刊-2026.10.09


## 前端技术
- [Claude Code Mods 扩展开发上手](https://claude.dev/blog/getting-started-with-claude-code-mods/)
  <br>Claude Code 新增 Mods 机制，允许用 JavaScript 扩展智能体编码工具，实现事件监听、行为修改和自定义 UI。Addy Osmani 用约 80 行代码演示了一个实时展示上下文窗口预测的 Mod，展示了 agentic 编码工具进入可编程时代的方向，对前端工程师做开发工具链创新很有启发。

- [NestJS 12.1 内置 Cookie 与 CSRF 防护](https://github.com/nestjs/nest/releases/tag/v12.1.0)
  <br>NestJS 12.1 新增内置 Cookie 支持、CSRF 防护和默认安全响应头，服务端框架开箱即用的安全能力更完整。对 Node 后端团队来说，可以减少一票第三方中间件依赖，值得升级体验。

- [Astro React 集成迁移至 Oxc 编译](https://github.com/withastro/astro/releases/tag/@astrojs/react@7.0.0)
  <br>@astrojs/react 7.0 将 Babel 换成 Oxc，带来更快的编译速度，并通过 compiler: true 选项支持 React Compiler。Astro 生态持续拥抱 Rust 工具链，这一迁移方向印证了前端编译基础设施的加速迭代趋势。

- [TanStack 发布 Redact 项目](https://tannerlinsley.com/posts/projecting-react)
  <br>TanStack 创始人 Tanner Linsley 发布 Redact，一个'React 的逻辑投影'，目标是 API 完全兼容但实现更简洁、包更小、性能更好，代价是不支持并发渲染。作为对 React 实现层面的重新思考，Redact 为理解 React 内部机制提供了独特视角，也测试了社区对替代实现的态度。

- [12 个替代 npm 包的 Node 内置模块](https://flaviocopes.com/node-builtins/)
  <br>Flavio Copes 系统梳理了 12 个可以替代 axios、dotenv、nodemon、chalk 等常见 npm 包的 Node.js 内置模块，并标注了在 Node 24 LTS 中的稳定性等级和潜在坑点。对于希望精简依赖、降低供应链风险的前端团队，这是一份非常实用的参考指南。

- [React-Redux 9.4 引入 useSignalSelector](https://github.com/reduxjs/react-redux/releases/tag/v9.4.0-alpha.1)
  <br>React-Redux 9.4 Alpha 加入基于 signals 的 useSignalSelector 钩子，通过追踪每个 selector 读取的状态，让 dispatch 只重新执行数据发生变化的 selector，解决大型应用中每次 dispatch 重跑所有挂载选择器的性能瓶颈。这是 Redux 在响应式状态管理方向的重要探索。

## 扩展阅读
- [State of Devs 2026 开发者调查出炉](https://2026.stateofdevs.com/en-US/)
  <br>2026 年 State of Devs 调查覆盖 5000+ 名开发者，聚焦职业安全感、AI 使用与态度、工作场所与收入等话题，是观察开发者群体情绪与行业风向的重要样本。其中 AI 相关章节对理解当前开发者对智能编程工具的复杂心态很有参考价值。

- [TanStack Charts 背后的开源与 AI 之路](https://tannerlinsley.com/posts/ai-open-source-and-the-long-road-to-tanstack-charts)
  <br>Tanner Linsley 回顾 TanStack Charts 1.0 漫长开发历程，并分享了如今如何使用 AI Agent 辅助构建与维护开源库的工作流。Chart 1.0 的发布对 TanStack 生态是一大补齐，文中对开源维护者人机协作模式的思考尤其值得一读。

- [Shopify 用 LLM 将应用迁离 React Native](https://shopify.engineering/helix)
  <br>Shopify 工程团队披露了 Helix 项目：利用 LLM 将 App 从 React Native 迁移到 Swift 和 Kotlin 原生实现。这是大模型辅助大规模跨语言代码迁移的罕见一线案例，对 AI 时代还要不要跨端框架的讨论提供了真实工程数据。

- [前端统一架构：一个大一统视角](https://dev.to/playfulprogramming/the-grand-unifying-architecture-of-frontend-bhk)
  <br>SolidJS 创始人 Ryan Carniato 提出'前端统一架构'理论：HTMX、React、LiveView 等框架的差异本质上只是把导航、内容、即时 UI 反馈三项工作在客户端和服务端之间划分的位置不同。他同时展示了 Solid 2.0 如何覆盖整个光谱，为理解各类前端架构提供了极佳的统摄性框架。

- [90 后集体接管国产大模型](http://finance.sina.com.cn/jjxw/2026-10-06/doc-iniuhcmf1976626.shtml)
  <br>文章梳理了国产大模型公司的'90 后掌舵'现象：阿里千问负责人刘大一恒（1993 年生）、千问办公 CEO 陈宇森（1992 年生）、小米 MiMo 负责人罗福莉（1995 年生）等相继走上关键岗位。在 Transformer 问世不到十年的技术周期里，'论资排辈'失效，年轻一代开始接管技术路线与商业化压力，是观察中国 AI 产业人才结构的独特视角。

- [Sindre Sorhus 因 AI 垃圾关闭外部 PR](https://bsky.app/profile/sindresorhus.com/post/3mwtgzhv7uk2t)
  <br>高产包维护者 Sindre Sorhus 因遭遇大量 AI 生成的贡献垃圾（AI contribution spam），宣布禁用外部 pull request，但仍会继续维护自己的项目；SWC 也随之限制 PR 只接受可信贡献者。这一事件折射出 AI 编码工具普及后开源维护者面临的新型治理难题，值得整个社区讨论应对之策。

- [高级工程师'死亡螺旋'](https://sunilpai.dev/posts/the-senior-engineer-death-spiral/)
  <br>Cloudflare 工程师 Sunil Pai 撰文描述高级工程师的'死亡螺旋'：新角色中为了证明自己而长时间沉默做事，最终导致过劳甚至 burnout。文章直面资深工程师在换岗或晋升期的心理困境，对技术人管理精力和团队留住人才都有现实参考价值。

- [为什么开发者不'使用平台'？](https://nolanlawson.com/2026/10/03/why-dont-more-developers-use-the-platform/)
  <br>Nolan Lawson 撰文讨论一个长期困扰前端圈的问题：为什么开发者不愿意使用浏览器平台提供的能力，而更倾向自建抽象？文章从开发者心理、框架生态、兼容性焦虑等角度剖析'平台原语'被冷落的原因，对当前 Web 平台能力与框架关系的讨论很有启发。

## 资源推荐
- [Frimousse 轻量无样式 emoji 选择器](https://frimousse.liveblocks.io/)
  <br>Liveblocks 出品的 Frimousse 0.4 是一个轻量、无样式的 emoji 选择器组件，样式完全交由开发者定制，适合需要深度融入自身设计系统的产品。配合现代 React 的 headless 组件趋势，体积与灵活性兼备。

- [pdfcn 复制粘贴式 PDF 组件库](https://www.pdfcn.dev/)
  <br>pdfcn 采用 shadcn 的思路做 PDF 生成，提供表格、页眉、列表、发票报告等可复制粘贴的组件。渲染基于 Takumi 或 Forme 两个 WASM 引擎，无需无头浏览器即可在浏览器端生成 PDF，为需要 PDF 导出能力的应用提供了轻量、现代的替代方案。

- [PR Comment Inbox 评审评论收件箱](https://humanwhocodes.com/blog/2026/09/introducing-pr-comment-inbox/)
  <br>Nicholas Zakas 发布的 PR Comment Inbox，为 GitHub 评审评论提供邮件式收件箱体验，支持线程聚合、已读/未读状态管理。对于在多个仓库间维护大量 open source 项目的开发者来说，这个工具能显著降低评审评论的跟踪成本，是 GitHub 原生通知体验的实用增强。

- [CVE Lite CLI 安全扫描工具](https://owasp.github.io/cve-lite-cli/)
  <br>OWASP 支持的开源安全扫描器，读取 lockfile 并对照 OSV 与 npm 安全公告，直接给出需要执行的 npm/pnpm/Yarn/Bun 升级命令，包括传递依赖问题应升级的父包。对前端团队来说，这是把依赖安全扫描融入日常开发流程的轻量利器，无需复杂配置即可获得可执行的修复建议。
