# 前端&AI技术双周刊-2026.09.10


## 前端技术
- [Bun 1.4.1 与 1.4.2 发布](https://bun.com/blog/bun-v1.4.1)
  <br>空闲内存显著下降（Next.js SSR 从 222MB 降到 142MB），Bun.serve 支持与 HTTP/1.1 同端口 HTTP/2，Bun.write 支持流式写盘，性能继续逼近并部分超越 Node

- [Zod 4.5 发布 预编译加速解析](https://zod.dev/blog/zod-4-5)
  <br>z.compile() 预编译可加速解析 3-9 倍，schema 内存占用降低 9 倍，z.validate() 快速路径对无效数据最多快 16 倍，表单与接口校验场景收益明显

- [Vitest 5.0 发布 更快与内置回放](https://vitest.dev/blog/vitest-5.html)
  <br>React SPA 基准提速约 15%，内置 trace 视图可回放浏览器测试过程，迁移指南覆盖破坏性变更，前端测试栈值得升级

- [NestJS 12 发布 全面转向 ESM](https://trilon.io/blog/nestjs-12-is-now-available)
  <br>8 月 28 日正式发布，核心包以 ESM 交付，默认 Vitest 和 oxlint，支持 Rspack 与 Standard Schema 校验，CLI 升级流程智能保留既有模块格式，是 Node 生态向 ESM 迁移的重要一步

- [htmx 4.0 正式发布](https://four.htmx.org/announcements/2026-08-28-htmx-4.0.0-is-released)
  <br>两年来首个大版本，包含大量变更，不依赖前端框架即可为服务端渲染页面添加交互，适合关注轻量 Web 架构的团队

- [Safari 重写模块加载器修复顶层 await](https://webkit.org/blog/18227/fixing-top-level-await-in-safari/)
  <br>Safari 27 通过自底向上重写模块加载器实现了顶层 await 的完整规范兼容，文章解释了多年"cannot access before initialization"错误的根源，ES 模块在 Safari 上终于可以放心使用

- [Next.js Turbopack 分块策略详解](https://nextjs.org/blog/turbopack-chunking)
  <br>从 Network 面板讲起，用官方站点打包数据拆解打包器在请求数与代码量之间的权衡，"8 个 chunk 可能比 355 个更重"这一反直觉结论很有冲击力，Next.js 16.3 还提供了实验性调优选项

- [Next.js 用 Agent 一个月关闭 1500 个 GitHub Issue](https://nextjs.org/blog/how-we-closed-1500-github-issues)
  <br>Next.js 团队用自研 Agent 研究积压的 issue 队列，维护者复核后一个月内关闭 1462 个 issue，是 AI 赋能开源项目治理的绝佳案例，对团队用 AI 做工程管理很有启发

- [React 19.3 发布：View Transitions 与 Fragment Refs](https://react.dev/blog/2026/09/09/react-19-3)
  <br>React 19.3 正式发布，新增 View Transitions、Fragment Refs、browser()、Trusted Types 等特性，是最近半年 React 最重要的功能更新，关注框架生态的开发者必看
